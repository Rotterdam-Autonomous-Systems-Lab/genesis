**2026-10-18 — Not executed. No Experiment 002 test count, result or benchmark exists.** See the [experiment](EXPERIMENT_002.md), [architecture](../architecture/EXPERIMENT_002_ARCHITECTURE.md) and [threat assumptions](EXPERIMENT_002_THREAT_MODEL.md).

## Method, fixtures and layers

Use separate contract unit/adversarial tests, finite fuzz/stateful accounting tests, signature interoperability tests, separate-process live-chain integration and standalone end-to-end runs. Synthetic funds and loopback temporary Anvil only. Do not modify or weaken the Experiment 001 suite; run it as regression/control evidence and report its counts separately. Exact new test counts are determined by the future implementation, not invented here.

Predeclare fixed seeds, corpus, run count and budgets before execution. Proposed minimum: two fresh normal runs, one requester-refusal run, one requester-offline-after-funding run, and every scenario row below. Proposed fuzz budget: 256 cases per arithmetic/binding property; proposed stateful budget: 128 runs of depth 64 with funding/claim/refund/withdraw/revoke/concurrent-agreement actions. These are planned bounded budgets, not completed executions. For callbacks unreachable with EOA-only payees, use a test-only adversarial receiver/accounting harness and label that evidence as defense in depth, not a supported contract-wallet path. Refund integration tests may advance trusted Anvil time after the bounded no-claim interval; record the adjustment and enforce the same canonical timestamp checks. Never change the deadlines to make a run pass. Every mandatory scenario requires an assertion about chain state/accounting and any claimed evidence, not just a caught exception. Retain failing seeds and distinguish expected attack rejection from fixture errors or inconclusive runs.

## Measurements and result ledger

For each run record scenario/seed, code/dependency identities, run/chain/deployment IDs, public agent addresses/PIDs, signed-term digests, input/output and independent expected value, canonical funding observation, first submission/inclusion/credit/withdrawal times and remaining deadline slack, intended and actual transition, transaction count/hash/status/gas/block/timestamp, principal/credits/balance/withdrawal deltas, payload sizes, wall-clock duration, recovery classification and child exit status. Gas and wall time are measured only after implementation; do not infer production performance or market fees. Agent key values and raw signed transactions are excluded.

Report all attempted attacks, successful unauthorized payouts (target zero), invalid results paid (target zero), duplicated payments (target zero), unexpected accounting deltas (target zero), requester-veto failures **within the timely-inclusion premise** (target zero), non-inclusion counterexamples, refunds, reverts and inconclusive runs. Keep transaction gas separate from principal. Correct work with no timely claim is not a false-positive payout and not evidence of unconditional fairness.

## Review and exit criteria

All mandatory safety tests and both normal runs must pass, all P2 properties have direct evidence, requester-offline/refusal variants collect correctly when timely included, invalid/no-claim paths refund deterministically, finite fuzz/stateful budgets finish without unexplained failures, and original Experiment 001 regressions remain intact. Document every excluded scenario and failure; an untested core property blocks a positive gate. Require reviewed implementation/digest schemas, dependency pins/maintenance assessment, fresh-checkout commands, CI and adversarial review before claiming experimental acceptance. No existing CI result constitutes Experiment 002 execution evidence.

Proposed [ADR 0002](../adr/0002-experiment-002-fair-exchange.md) requires a separate implementation authorization. If the public-output/non-inclusion counterexample is considered unacceptable for the research question, reject or revise the question before implementation rather than promise a guarantee this mechanism lacks.
