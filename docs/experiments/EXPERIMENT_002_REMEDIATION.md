## Late-funding investigation

[Initial review CI](https://github.com/Rotterdam-Autonomous-Systems-Lab/genesis/actions/runs/39139135792) failed at canonical funding revert (57/58 Experiment 002 tests passed); all six then-new review tests passed. [Final Task 013 CI](https://github.com/Rotterdam-Autonomous-Systems-Lab/genesis/actions/runs/39139675027) passed without an implementation fix, preserving the scheduling question.

The old fixture mined an empty block at fundBefore-1 and then relied on process wake-up, signing and RPC submission to complete before the next automined timestamp crossed expiry. Setting the latest block did not reserve the next inclusion time. The new bounded probe repeats that sequence with a deliberate **1.1-second scheduling delay**: the real receipt timestamp is at/after fundBefore, status is zero, nonce remains unused, locked principal remains zero and wallet debit is exactly receipt gas cost. No signature, cap or accounting violation is needed to trigger the failure. The previously added forced-at-expiry test remains as a separate deterministic contract boundary control.

Controlled valid-late funding now queues first and mines at the fixed last-valid timestamp. The provider's valid result is still deliberately held until claimBefore, then rejected and refunded as before. A poll cannot create authority or increase a timeout; it must finish within existing bounds. Pending-pool and chain control rely on the same trusted isolated Anvil, not a public mempool guarantee. Failed funding diagnostics explicitly label retained observations as **not currently verified**; unknown/contradictory evidence is not repaired or promoted to success. No original failure is deleted or reclassified as a successful exchange.

## Evidence checks and local timing

The supervisor checks the cryptographic agreement in decoded included funding, not merely the parties' final JSON claims. It reconstructs terminal outcomes/entitlements, then checks record, nonce, owner credits including the deployer, locked/total liabilities, role wallets and contract balance at one block number. A second identical snapshot and unchanged head hash detect changes/inconsistency during audit. Signing clients compare known terminal events with repeated pinned record reads. This catches the reviewed partial contradictions; it cannot make a wholly fabricated ledger authentic.

Transaction policy still reserves 6*10^15 synthetic wei before every attempted signature; deployer/A/B attempt caps remain 1/8/8, with closing slots. Gas <=2,000,000, max fee <=3 gwei, priority <=1 gwei; principal <=signed max<=10^15. A failed/uncertain action never restores reservation or grants an automatic fresh nonce/fee escalation. There are no top-ups. Deadline exceptions and evidence contradictions latch new submissions; diagnostic reads cannot reset the latch.

Before/after RPC checks use the existing pinned Web3 middleware API and disabled-CCIP/loopback transport. Shared monotonic time assumes one host; it is not a transferable network clock. The watchdog/RSS measurement is cooperative and cleanup remains best effort under trusted OS operation. Host pause/SIGKILL, kernel/filesystem stalls, consistently dishonest RPC, key loss, rollback/finality, public disclosure and unavailable/censored callers remain outside guarantees. No unconditional fair exchange or production assurance follows.
