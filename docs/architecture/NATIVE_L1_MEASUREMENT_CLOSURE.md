## Cost boundaries

- **Deterministic behavior:** independently checked barriers, changed logical rows, success/rejection classifications, native versus injected conflicts, submissions/queries, journal flushes and client classifications. Sequential fresh-reference stress remains sequential, not a parallel-throughput test.
- **Verification:** count every model-level input/output/identity SHA-256 call and input byte, parse call/byte, Ed25519 verification, predicate and covenant input check. Signature-library internal hashing/arithmetic is opaque inside the signature operation, not reported as zero work. Client hashing/signatures are separate. Reads/writes remain candidate-specific units; logical row changes provide a common descriptor without deleting native work.
- **Representation:** initial/peak native retained state, immutable term/key/alias/label registry serialized to a separate actual file, total retained native+registry bytes, client journal high-water and transport/logical/wrapper sizes. Histories still differ: UTXO retains full spent outputs, others compact history. No family-wide storage ranking follows. No pruning/consolidation or removed fsync is used to obtain a pass.
- **CPU/time:** worker operation/build/include, full native persistence, IPC decode/encode and observation-production components are separate. Parsing/signature component timings overlap the containing operation and must not be summed twice. A second resource envelope captures CPU, component timers and peak RSS after encoding/flushing the large final audit response; aggregate process CPU/end-to-end time include that work. Harness CPU and process-lifetime peak RSS upper bound are reported separately; the latter is not falsely presented as a reset per-case peak.
- **Containment:** Linux pins worker/client to the same allowed CPU and keeps hard per-process address-space/CPU limits. An external20ms watchdog samples their aggregate CPU using Linux process ticks, kills both on120 CPU/180 wall seconds, and validates the final sample. Sampling/tick quantization and small kill overshoot are disclosed; any observed excess is HOLD. This is laboratory containment, not consensus gas metering. macOS cannot provide equivalent enforcement and cannot count as a reference-profile resource pass.
- **Failure boundary:** retain checked-prefix length, traffic, last known client exposure, sampled CPU and the error. An attempted transition may be included before a failed observation; timeout is never proof of non-inclusion. Native power-loss recovery is not tested by client journal reload.

Every request, wrapper, signed input, receipt and oracle query/reply remains charged to the client proxy. Harness debug projections are separately measured, not hidden proof/indexer traffic. The10KiB/s overlay is unchanged, as are16MiB/client,64KiB transport,256MiB state,1MiB journal,1GiB worker/128MiB client,32 pending,3 submissions/8 queries,30minute/model and15second cleanup limits.

## Reproduction plan

Two separately provisioned Ubuntu24.04 GitHub job environments install the complete unchanged hash-locked dependencies, CPython3.12.1 and PyCryptodome3.24.1, then run the exact same source and public signed stress artifact. Host-identity hashes, replica IDs and workflow/job provenance distinguish environments even when OS strings match. A third job runs offline completeness, golden-trace, budget and deterministic cross-environment checks without importing candidate implementations. Two jobs are shared-source reproduction, not independent implementations or a security audit; host/load/cache differences remain explicit.

The original local S09 reproduction and isolated in-memory cProfile diagnostic remain separate from these scored batches. The profile excludes persistence, IPC, client and assertions; its elapsed time cannot substitute for end-to-end comparison. Final acceptance and measured outcomes belong in the [Task020 report](NATIVE_L1_TASK020_RESULTS.md), not this preregistered contract. No production performance, consensus/finality, physical delivery, native proof or adoption guarantee follows.
